# 错误处理

API 使用标准 HTTP 状态码表示请求结果。错误响应通常包含可读消息。

## 常见状态码

| 状态码 | 含义 | 建议处理方式 |
| --- | --- | --- |
| `400` | 请求参数错误 | 检查模型、字段类型和必填参数 |
| `401` | 未认证 | 检查 API Key 和 Authorization 格式 |
| `403` | 无访问权限 | 检查令牌权限和账号状态 |
| `404` | 路径或模型不存在 | 检查接口路径与模型 ID |
| `429` | 请求过多或额度不足 | 降低频率，并检查账号余额和限额 |
| `500` | 服务内部错误 | 稍后重试；持续发生时联系支持 |
| `502` | 上游服务异常 | 使用指数退避进行有限重试 |
| `503` | 服务暂时不可用 | 稍后重试或切换模型 |
| `504` | 上游响应超时 | 减少生成长度，稍后重试 |

## 错误响应

```json
{
  "error": {
    "message": "Incorrect API key provided",
    "type": "invalid_request_error",
    "code": "invalid_api_key"
  }
}
```

## 重试策略

只对临时错误重试，并使用指数退避：

```text
第 1 次：等待 1 秒
第 2 次：等待 2 秒
第 3 次：等待 4 秒
```

建议加入少量随机抖动，并设置最大重试次数。参数错误和认证错误不应自动重试。
